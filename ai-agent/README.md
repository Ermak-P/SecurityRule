## 1. Требования

| Что | Минимум | Рекомендуется |

## 2. Установка (один раз)

### Шаг 1 — Запустить Ollama в Docker

```bash
# Из папки ai-agent (там где docker-compose.yml)
cd ai-agent
docker compose up -d

# Проверить статус
docker compose ps
# Должно быть: Status = Up
```

### Шаг 2 — Скачать языковую модель

```bash
# Основная модель (~4.5 GB, скачивается один раз)
docker exec -it ollama ollama pull qwen2.5-coder:7b

# Проверить что модель скачалась
docker exec -it ollama ollama list
# Вывод: NAME                    ID              SIZE
#         qwen2.5-coder:7b       ...             4.7 GB
```

> **Выбор модели:**
> | Модель | Размер | RAM | Качество | Скорость |
> |---|---|---|---|---|
> | `llama3.2:3b` | ~2 GB | 4 GB | среднее | быстро |
> | `qwen2.5-coder:7b` | ~4.5 GB | 8 GB | **хорошее** | нормально |
> | `qwen2.5-coder:14b` | ~8 GB | 16 GB | отличное | медленно |
> | `codellama:7b` | ~4 GB | 8 GB | хорошее | нормально |

### Шаг 3 — Собрать агента

```bash
cd ai-agent/src/DotnetAgent
dotnet build
```

## 3. Запуск агента

### Вариант А — передать путь аргументом (рекомендуется)

```bash
cd ai-agent/src/DotnetAgent

# Windows
dotnet run -- "C:\Projects\MyApp"

# Linux / macOS
dotnet run -- "/home/user/projects/my-app"

# Указать конкретный проект внутри репозитория
dotnet run -- "/path/to/SecurityRule/src/SecurityRule.Web"
```

### Вариант Б — без аргументов (агент спросит сам)

```bash
cd ai-agent/src/DotnetAgent
dotnet run
# 📁 Введите путь до .NET проекта: C:\Projects\MyApp
```

### Вариант В — через переменную окружения

```bash
# Linux / macOS
export DOTNET_AGENT_PROJECT_PATH="/home/user/projects/my-app"
dotnet run

# Windows PowerShell
$env:DOTNET_AGENT_PROJECT_PATH = "C:\Projects\MyApp"
dotnet run
```

### Вариант Г — через файл конфигурации

```bash
# Создать agent.json в папке проекта (см. раздел 8)
dotnet run -- --config=agent.json
```

## 4. Интерфейс консоли

```
> ваш запрос          ← жёлтый промпт, здесь вводите текст

🔧 list_files(...)    ← агент использует инструмент (отображается в реальном времени)
✓ Результат: ...      ← результат инструмента

Ответ агента:         ← итоговый ответ выводится по мере генерации (streaming)
В проекте 15 файлов: ...
```

**Цвета:**
- 🟡 Жёлтый — промпт ввода (`>`)
- 🟢 Зелёный — успешные операции, подтверждения
- 🔴 Красный — ошибки
- ⚪ Белый — ответ агента

## 5. Все инструменты агента

Агент самостоятельно решает, какой инструмент использовать. Вы можете явно упомянуть нужное действие в запросе.

### 📁 Файловая система

| Инструмент | Что делает | Пример использования в запросе |
|---|---|---|
| `list_files` | Список файлов проекта с фильтром | «покажи структуру», «найди все .cs файлы» |
| `read_file` | Читает содержимое файла | «прочитай Program.cs», «покажи содержимое файла» |
| `write_file` | Перезаписывает файл полностью | «измени файл», «обнови содержимое» |
| `create_file` | Создаёт новый файл | «создай класс», «добавь новый файл» |
| `search_in_files` | Полнотекстовый поиск по проекту | «найди все TODO», «где используется ILogger» |

### 🔬 Анализ кода (Roslyn)

| Инструмент | Что делает |
|---|---|
| `get_class_info` | Показывает поля, свойства, методы класса (сигнатуры) |
| `get_usages` | Находит все места использования класса или метода |
| `get_dependencies` | Показывает зависимости через `using` и DI (внедрение зависимостей) |
| `patch_method` | Заменяет тело одного метода без перезаписи всего файла |

### 🔨 Сборка и тесты

| Инструмент | Что делает |
|---|---|
| `dotnet_build` | Запускает `dotnet build` и возвращает ошибки компилятора |
| `dotnet_test` | Запускает `dotnet test` и показывает упавшие тесты |

### 🗃️ Git

| Инструмент | Что делает |
|---|---|
| `git_status` | Показывает изменённые, новые, удалённые файлы |
| `git_diff` | Diff изменений (весь или по конкретному файлу) |
| `git_commit` | Создаёт коммит с текущими изменениями |
| `git_log` | История коммитов |

### 🧪 Генерация тестов

| Инструмент | Что делает |
|---|---|
| `generate_tests` | Генерирует заготовку xUnit-тестов для класса (по одному тесту на каждый метод) |

### 🔍 RAG (семантический поиск, опционально)

Активируется автоматически если запущен ChromaDB.

| Инструмент | Что делает |
|---|---|
| `rag_index` | Индексирует файлы проекта в векторную базу |
| `rag_search` | Семантический поиск по коду (по смыслу, а не по точному тексту) |

## 7. Служебные команды

Введите в промпте `>` вместо обычного запроса:

| Команда | Что делает |
|---|---|
| `помощь` / `help` | Показать справку |
| `инструменты` / `tools` | Список доступных инструментов с описанием |
| `история` | Показать историю текущего разговора |
| `очистить` / `clear` | Очистить историю (начать новый контекст) |
| `undo` / `отменить` / `откат` | Откатить последнее изменение файла |
| `сессии` / `sessions` | Список сохранённых сессий |
| `выход` / `exit` / `quit` / `q` | Выйти из программы |

### Пример использования откатить

```
> Добавь поле _cache в класс ServerRepository
  [агент вносит изменение]

> undo
✓ Откат изменения ServerRepository.cs
  [файл восстановлен к предыдущему состоянию]
```

### Продолжение предыдущей сессии

При следующем запуске агент предложит продолжить последнюю сессию:

```
Найдена предыдущая сессия: Сессия 2024-01-15 (15.01.2024 10:30)
Продолжить? (д/н): д
✓ Загружено 8 сообщений из сессии
```

История разговора (контекст) восстановится — агент «вспомнит» что обсуждалось ранее.

## 8. Конфигурация (agent.json)

Создайте файл `agent.json` в папке `ai-agent/src/DotnetAgent/` для постоянных настроек.

### Минимальный конфиг

```json
{
  "ProjectPath": "C:\\Projects\\SecurityRule\\src\\SecurityRule.Web",
  "ModelName": "qwen2.5-coder:7b"
}
```

### Полный конфиг со всеми параметрами

```json
{
  "ProjectPath": "C:\\Projects\\SecurityRule\\src",
  "OllamaUrl": "http://localhost:11434",
  "ModelName": "qwen2.5-coder:7b",
  "FastModelName": "llama3.2:3b",
  "SmartModelName": "qwen2.5-coder:14b",
  "MaxToolCallsPerRequest": 10,
  "Temperature": 0.1,
  "ContextWindowSize": 8192,
  "EnableStreaming": true,
  "EnableSessionPersistence": true,
  "ChromaDbUrl": "http://localhost:8000",
  "EmbeddingModel": "nomic-embed-text"
}
```

| Параметр | По умолчанию | Описание |
|---|---|---|
| `ProjectPath` | `""` | Путь до .NET проекта |
| `OllamaUrl` | `http://localhost:11434` | URL Ollama API |
| `ModelName` | `qwen2.5-coder:7b` | Основная модель |
| `FastModelName` | `null` | Быстрая модель для простых запросов |
| `SmartModelName` | `null` | Умная модель для сложного кода |
| `MaxToolCallsPerRequest` | `10` | Лимит вызовов инструментов за один запрос |
| `Temperature` | `0.1` | Творческость (0.0 = точный, 1.0 = творческий) |
| `ContextWindowSize` | `8192` | Размер контекстного окна в токенах |
| `EnableStreaming` | `true` | Стриминг ответов (как в ChatGPT) |
| `EnableSessionPersistence` | `true` | Сохранять историю между сессиями |
| `ChromaDbUrl` | `http://localhost:8000` | URL ChromaDB для RAG |
| `EmbeddingModel` | `nomic-embed-text` | Модель для embeddings (RAG) |

### Запуск с конфигом

```bash
dotnet run -- --config=/path/to/agent.json
```

Агент ищет `agent.json` автоматически в следующих местах (по порядку):
1. Путь из `--config=`
2. `agent.json` в текущей папке
3. `~/.dotnet-agent/agent.json`

## 9. Расширенные режимы

### Поддержка GPU (NVIDIA)

Раскомментируйте блок в `docker-compose.yml`:

```yaml
deploy:
  resources:
    reservations:
      devices:
        - driver: nvidia
          count: 1
          capabilities: [gpu]
```

Требуется установить [nvidia-container-toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/install-guide.html).

### MCP-режим (интеграция с VS Code / Cursor)

Агент может работать как [MCP-сервер](https://modelcontextprotocol.io/) — это позволяет подключить его к VS Code с расширением Copilot или к редактору Cursor.

```bash
# Запуск в MCP-режиме (stdio транспорт)
dotnet run -- --mcp
```

В `mcp.json` конфигурации VS Code / Cursor:

```json
{
  "servers": {
    "dotnet-agent": {
      "command": "dotnet",
      "args": ["run", "--project", "/path/to/ai-agent/src/DotnetAgent", "--", "--mcp"],
      "env": {
        "DOTNET_AGENT_PROJECT_PATH": "/path/to/your/project"
      }
    }
  }
}
```

### RAG — семантический поиск (ChromaDB)

Позволяет искать по коду по смыслу (не только точный текст).

```bash
# Запустить ChromaDB
docker run -d -p 8000:8000 --name chromadb chromadb/chroma

# Скачать модель для embeddings
docker exec -it ollama ollama pull nomic-embed-text

# Запустить агента — RAG активируется автоматически
dotnet run -- "/path/to/project"
# ✓ ChromaDB доступен — RAG инструменты активированы
```

После этого можно:

```
> Проиндексируй проект
> Найди код который отвечает за валидацию данных
> Покажи похожие примеры использования паттерна Repository
```

### Олова на другой машине

Если Ollama запущен на другом компьютере в локальной сети:

```json
{
  "OllamaUrl": "http://192.168.1.100:11434"
}
```

## 10. Устранение неполадок

### ❌ «Ollama не отвечает»

```
Ollama не отвечает по адресу: http://localhost:11434
```

**Решение:**
```bash
cd ai-agent
docker compose up -d
docker compose ps   # убедиться что Status = Up
```

---

### ❌ «Модель не найдена»

```
⚠️ Модель 'qwen2.5-coder:7b' не найдена!
```

**Решение:**
```bash
docker exec -it ollama ollama pull qwen2.5-coder:7b
```

---

### ❌ «Директория не найдена»

```
❌ Ошибка: директория не найдена: 'C:\Projects\App'
```

**Решение:** Убедитесь что путь существует и указан без опечаток:
```bash
# Windows
dir "C:\Projects\App"

# Linux / macOS
ls /home/user/projects/app
```

---

### ❌ Агент работает очень медленно

**Причины и решения:**
1. Нет GPU — на CPU 7B-модель отвечает 1-3 минуты. Рассмотрите `llama3.2:3b` (быстрее)
2. Мало RAM — увеличьте или используйте меньшую модель
3. Включите GPU-поддержку (см. раздел 9)

Проверить использование ресурсов:
```bash
docker stats ollama
```

---

### ❌ «Доступ запрещён: путь выходит за пределы проекта»

Это защита от выхода за пределы проекта. Убедитесь, что путь в запросе относительный и указывает на файл внутри указанной при запуске директории.

---

### ❌ Агент застрял в цикле инструментов

Агент ограничен `MaxToolCallsPerRequest` (по умолчанию 10) вызовами за запрос. Если задача требует больше шагов:

```json
{
  "MaxToolCallsPerRequest": 20
}
```

## 11. Архитектура

### Технологический стек

| Компонент | Технология | Описание |
|---|---|---|
| LLM сервер | [Ollama](https://ollama.com/) | Запускает языковые модели локально |
| Модель | `qwen2.5-coder:7b` | Специализирована для работы с кодом |
| Агент | .NET 9 Console App | Консольное приложение на C# |
| Анализ кода | Roslyn (Microsoft.CodeAnalysis) | Разбор C# AST |
| Git | LibGit2Sharp | Нативная Git-интеграция |
| Сессии | SQLite | Хранение истории разговоров |
| RAG | ChromaDB + Ollama embeddings | Семантический поиск |
| Контейнер | Docker | Изоляция Ollama и ChromaDB |

### Паттерн ReAct

Агент использует паттерн **ReAct** (Reasoning + Acting):

```
Пользователь: "Добавь логирование в ServerRepository"
      ↓
[THINK] LLM решает: нужно прочитать файл
      ↓
[ACT]  get_class_info("ServerRepository")
      ↓
Результат: поля, методы, зависимости
      ↓
[THINK] LLM планирует изменение
      ↓
[ACT]  patch_method("GetAllAsync", новое тело метода)
      ↓
Результат: файл обновлён
      ↓
[THINK] LLM решает: проверить сборку
      ↓
[ACT]  dotnet_build()
      ↓
Результат: Build succeeded
      ↓
[THINK] Всё готово, формирую ответ пользователю
      ↓
Пользователь видит: "Добавил ILogger в GetAllAsync..."
```

### Структура проекта агента

```
ai-agent/
├── docker-compose.yml              # Ollama (и опционально ChromaDB)
└── src/DotnetAgent/
    ├── agent.json                  # Ваш конфиг (создаёте сами, не коммитить!)
    ├── DotnetAgent.csproj
    ├── Program.cs                  # Точка входа, инициализация
    ├── Config/
    │   └── AgentConfig.cs          # Все настройки с дефолтами
    ├── Core/
    │   ├── Agent.cs                # Главный цикл (ReAct), служебные команды
    │   ├── OllamaClient.cs         # HTTP клиент для Ollama API
    │   ├── SessionStore.cs         # SQLite хранилище сессий
    │   └── UndoManager.cs          # Откат изменений файлов
    ├── Models/
    │   └── OllamaModels.cs         # DTO для Ollama API
    ├── Tools/
    │   ├── IAgentTool.cs           # Интерфейс инструмента
    │   ├── ToolRegistry.cs         # Реестр инструментов
    │   ├── FileSystemTools.cs      # list_files, read_file, write_file, create_file, search_in_files
    │   ├── RoslynTools.cs          # get_class_info, get_usages, get_dependencies, patch_method
    │   ├── BuildTools.cs           # dotnet_build, dotnet_test
    │   ├── GitTools.cs             # git_status, git_diff, git_commit, git_log
    │   ├── TestGenerationTools.cs  # generate_tests
    │   └── RagTools.cs             # rag_index, rag_search (если ChromaDB доступен)
    ├── Mcp/
    │   └── McpServer.cs            # MCP stdio сервер (для VS Code / Cursor)
    └── Rag/
        └── ChromaClient.cs         # HTTP клиент для ChromaDB
```
